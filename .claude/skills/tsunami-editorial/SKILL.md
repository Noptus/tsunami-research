---

Run commands from the Tsunami Research checkout. Read [the weekly workflow](../../../docs/weekly-editorial.md) for the CLI and publication sequence.

### Draft an issue

1. Fix the week and the forecast window. Use the proposal command for the standard ±2% S&P 500 questions. An abstention records a calendar, feed, or timing gap. Add a named event only when its result has an official source and a precise decision rule.
2. Build a source manifest from primary documents. Record when each was first available and when it was retrieved. A date-only release needs a conservative availability bound. Capture a payload hash when you have the bytes and can handle them locally. Preserve source attribution and point-in-time ordering even when checking a historical issue.
3. Assess the baseline before adjusting it. Write the thesis, a plausible counterargument, and a condition that would change the estimate. Two tails on the same return are dependent. Separate evidence of a catalyst from evidence about the direction or magnitude of a move. Give a named event no numerical baseline if a relevant reference class is unavailable.
4. Prepare the packet and review the exact candidate with the editorial CLI. The tool checks the relationship between evidence, cutoff, baseline, and candidate. Read the evidence separately for factual accuracy and judgment. If any probability, wording, or source changes, run the review again.
5. Publish through the dated immutable GitHub release only when the issue can still be prospective. Use the existing release and attestation workflow. The review receipt describes local checks. The GitHub receipt establishes publication time.

### Settle an issue

Use the existing resolver for market thresholds. For a named event, follow the issue's own resolution rule and source list. Check each source's coverage through the deadline and wait until any stated negative-resolution barrier. Record the outcome with the decisive links and a short explanation. If a source is missing or ambiguous, leave the forecast open unless the frozen void rule applies.
